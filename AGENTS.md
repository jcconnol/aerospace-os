# Aerospace OS agent instructions

Follow the global coding standards provided by the user.

## Usable checkpoints

After making changes that form a usable checkpoint, verify the relevant behavior, commit the changes, and push the current branch to its configured remote. Do this even if the larger feature or project is not finished. A checkpoint should be coherent and usable, with any limitations clearly documented; do not wait for the entire task to be complete.

Commit only files relevant to the checkpoint. Keep generated files, build artifacts, credentials, and unrelated user changes out of commits. If verification or pushing fails, report the failure and what remains local. Do not force-push unless explicitly authorized.
